# Development vs. Production Execution Comparison

**Project:** VisionPilot  
**Date:** October 3, 2026  
**Auditor:** Principal Software Engineer & QA Lead  
**Context:** Investigating why features behave differently between development tests and production installed EXE.

---

## 1. Comparative Analysis Matrix

| Component | Development Environment (`pytest` / direct Python) | Production Packaged Executable (`VisionPilot.exe`) | Key Difference | Root Cause |
| :--- | :--- | :--- | :--- | :--- |
| **Application Lifecycle & UI Execution** | Tests programmatically construct `ActionRequest`s and directly call `file_executor.execute()` or `verif_engine.verify_action()` with pre-wired paths. | `MainWindow` presents a two-phase UI: Command submission generates a `TaskPlan` preview, requiring the user to locate and click an inner `"Execute Plan"` button. | In development, tests invoke execution directly. In production, users enter a command expecting autonomous execution ("See. Understand. Act. Verify.") but the application stops at "Plan Ready" without auto-executing. | **UI Orchestration Disconnect:** Command submission only plans; execution requires secondary manual trigger, misleading users into thinking the application froze. |
| **Task Cancellation State** | Tests instantiate fresh `TaskPlanner()` and `ActionExecutor()` instances per test fixture or function. | Single long-lived global singleton instances of `task_planner` and `action_executor` run throughout the process lifetime. | When a user cancels a task or clicks Cancel, `task_planner.cancel()` sets `self._is_cancelled = True`. This flag was never reset on subsequent `create_plan()` or `execute_plan()` calls. | **Sticky Cancellation Flag (P0):** After one cancellation, the planner and executor permanently reject all subsequent user commands with `"TaskPlanner already cancelled before planning command"`. |
| **Multi-Step Plan Parameter Forwarding** | `test_e2e_workflows.py` explicitly captures `target_pdf = found_pdfs[0]` from Step 1 and manually populates `parameters={"source_path": str(target_pdf)}` for Step 2 (`RENAME_FILE`). | Production `TaskPlanner` generates static symbolic references: Step 1 finds the latest PDF, but Step 2 has `target="selected_file"` without dynamic runtime binding to Step 1's output. | In production, `FileActionExecutor` attempts to resolve the literal string `"selected_file"`, which does not exist on disk, causing immediate `FileNotFoundError`. | **Missing Dynamic Step Output Binding (P0):** Step 2 and Step 3 in file workflows do not ingest the runtime output (`found_path`) of Step 1 (`FIND_FILE`). |
| **Verification State Accumulation** | Tests run single plan executions with isolated `VerificationEngine` instances or mock verifications. | `ActionExecutor` maintains an instance attribute `self.step_verifications: List = []`. | `self.step_verifications` was never cleared at the beginning of `execute_plan()`. On any subsequent execution, verifications from prior runs accumulate. | **State Leak in Task Verification (P1):** `TaskVerifier` counts total verified steps against the current plan step count. If 2 verifications exist for a 1-step plan, `verified_steps == total_steps` evaluates to `2 == 1` (`False`), falsely failing verification with `"Task failed (2/1 steps verified)"`. |
| **Voice Transcription (STT)** | Tests use `MockSTTProvider` or mock the underlying recognizer responses. | Production uses `LocalSTTProvider` backed by `speech_recognition`. | PocketSphinx is not installed in the Python/frozen distribution, and the native Windows SAPI fallback (`_recognize_via_sapi`) is a stub that hardcoded returns `None`. | **Unimplemented Local STT Engine (P1):** All spoken voice inputs unconditionally fail with `VoiceError: Could not understand the spoken words. Please speak clearly.` |
| **Non-Whitelisted Application Launches** | Tests launch allowlisted applications (`notepad.exe`, `calc.exe`). | User entered real-world commands such as `"open youtube"`. | `LocalReasoningProvider._plan_application_launch` only checked for `["notepad", "calculator", "explorer", "edge", "settings", "terminal"]`. Anything else fell back to Notepad or generic desktop observation. | **Incomplete Intent Mapping (P2):** Web URLs and unlisted applications default to Notepad instead of opening in the default browser or reporting clear feedback. |
| **Paths & Working Directory** | Tests run with CWD set to workspace root (`c:\Users\rishi\Desktop\Vision Pilot`). | Packaged app runs from `%LOCALAPPDATA%\Programs\VisionPilot\` or arbitrary shortcut CWD. | Paths for data and logs correctly resolve via `get_application_paths()` to `%LOCALAPPDATA%\VisionPilot\data` and `logs`. | **Working Correctly:** Path resolution for SQLite and logs is healthy in production. |
| **Hardware & DLL Loading** | Runs in Python 3.14 x64 via Prism with access to site-packages. | Bundled PyInstaller folder contains all PySide6, WinRT, UIA, and Win32 DLLs. | PyInstaller spec correctly bundles all submodules and native extensions. UIA extracted 115 elements in production log. | **Working Correctly:** No DLL or import errors detected in production log. |
